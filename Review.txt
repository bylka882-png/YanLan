## C1. Атомарная запись JSON-файлов

Файлы:
  src/util.rs — новая функция write_atomic.
  src/library.rs::Library::save — std::fs::write → util::write_atomic.
  src/library.rs::write_meta — то же.
  src/config.rs::Config::save — то же.
  src/builds.rs::save_cache — то же.
  src/mods.rs::save_cache — то же.

Текущее поведение:
Все сохранения используют std::fs::write(path, text). Если процесс убит
или питание пропало в момент записи, файл останется обрезанным.
Для library.json и .yanlan.json это означает потерю всех записей об
установленных модах или потерю метаданных сборки.

Проблема:
library.json, .yanlan.json, config.json — пользовательские данные, не
восстанавливаемые из сети. Обрезка = потеря. Кэши (builds.json, mods.json)
менее критичны (скачиваются заново), но единый механизм проще.

Что сделать:

1. В src/util.rs добавить:
   pub fn write_atomic(path: &Path, text: &str) -> Result<(), String> {
       let tmp = path.with_extension("json.tmp");
       if let Some(parent) = path.parent() {
           std::fs::create_dir_all(parent).map_err(|e| format!("{}: {e}", parent.display()))?;
       }
       let mut file = std::fs::File::create(&tmp).map_err(|e| format!("{}: {e}", tmp.display()))?;
       use std::io::Write;
       file.write_all(text.as_bytes()).map_err(|e| format!("{}: {e}", tmp.display()))?;
       file.sync_all().map_err(|e| format!("{}: {e}", tmp.display()))?;
       drop(file);
       std::fs::rename(&tmp, path).map_err(|e| format!("{}: {e}", path.display()))?;
       Ok(())
   }
   Расширение .json.tmp — чтобы find_game_root и подобные не путали
   временный файл с данными.

2. Заменить все std::fs::write в перечисленных функциях на util::write_atomic
   с пробросом ошибки через существующий Result (или через let _ = для
   кэшей, где ошибка не критична — но лучше пробросить в лог).

3. Config::save сейчас возвращает () и игнорирует ошибку. Оставить (), но
   логировать через eprintln! при ошибке — это не UI-путь.

Тест (в src/util.rs, mod tests):
#[test]
fn write_atomic_replaces_file() {
    let dir = std::env::temp_dir().join(format!("yanlan_atomic_{}", std::process::id()));
    let _ = std::fs::remove_dir_all(&dir);
    std::fs::create_dir_all(&dir).unwrap();
    let path = dir.join("test.json");
    std::fs::write(&path, "old").unwrap();
    write_atomic(&path, "new").unwrap();
    assert_eq!(std::fs::read_to_string(&path).unwrap(), "new");
    assert!(!dir.join("test.json.tmp").exists());
    let _ = std::fs::remove_dir_all(&dir);
}

Acceptance:
  Все std::fs::write для persistent JSON заменены.
  Тест write_atomic_replaces_file проходит.
  cargo test — 41 passed, 1 ignored.
  SOP.txt разделы 9.2, 9.3, 9.4 — упомянуть атомарную запись.

## C2. Гонка при записи library.json

Файлы:
  src/library.rs — новый мьютекс.
  src/jobs.rs — install_catalog_mods, install_local_archive, uninstall_mod, delete_game.

Текущее поведение:
Каждая из четырёх фоновых задач делает:
  let mut library = Library::load(&cfg.root_dir);
  // ... мутации ...
  library.save(&cfg.root_dir)?;
Если пользователь запускает установку мода в одну сборку и одновременно
удаляет мод из другой, оба потока читают одно состояние, каждый пишет своё,
последний выигрывает. Первый мод теряется.

Проблема:
Library — общий ресурс, но защита — только на уровне одного процесса
внутри одного потока. Параллельные jobs::spawn не сериализуются.

Что сделать:

1. В src/library.rs добавить:
   use std::sync::Mutex;
   static LIBRARY_LOCK: Mutex<()> = Mutex::new(());

   pub fn lock_library() -> std::sync::MutexGuard<'static, ()> {
       LIBRARY_LOCK.lock().unwrap_or_else(|e| e.into_inner())
   }
   unwrap_or_else(|e| e.into_inner()) — чтобы паника одного потока не
   отравляла мьютекс для остальных.

2. В src/jobs.rs в каждой из четырёх функций обернуть read-modify-write:
   let _guard = crate::library::lock_library();
   let mut library = Library::load(&cfg.root_dir);
   // ...
   library.save(&cfg.root_dir)?;
   // _guard отпускается в конце скоупа

3. App::reload_library в UI-потоке не блокируется мьютексом — это чтение
   без модификации, и оно увидит либо старое, либо новое состояние целиком
   (атомарное переименование из C1 гарантирует это).

Тест (интеграционный, в src/library.rs::tests):
#[test]
fn parallel_installs_do_not_lose_mods() {
    let root = std::env::temp_dir().join(format!("yanlan_race_{}", std::process::id()));
    let _ = std::fs::remove_dir_all(&root);
    std::fs::create_dir_all(root.join("games")).unwrap();
    let handles: Vec<_> = (0..10).map(|i| {
        let root = root.clone();
        std::thread::spawn(move || {
            let _guard = crate::library::lock_library();
            let mut lib = Library::load(&root);
            let mut item = InstalledMod::new(&format!("mod{i}"), &format!("Mod {i}"), "mod", "", "game", Vec::new());
            item.key = format!("mod{i}-0");
            lib.add(item);
            lib.save(&root).unwrap();
        })
    }).collect();
    for h in handles { h.join().unwrap(); }
    let lib = Library::load(&root);
    assert_eq!(lib.mods.len(), 10);
    let _ = std::fs::remove_dir_all(&root);
}

Acceptance:
  Тест проходит.
  install_catalog_mods, install_local_archive, uninstall_mod, delete_game
  держат мьютекс во время read-modify-write.
  При параллельной установке двух модов в разные сборки оба попадают в library.json.

Фоновые задачи живут, но UI о них не знает. Особенно заметно с
download_catalog_mod (кнопка «Скачать» у зависимости во время установки).

2. Переписать start_parallel_job:

       let title = title.into();
       if self.progress.is_none() {
           self.begin_job(title, progress);
       } else {
           self.pending_jobs.push((progress.id(), title, progress));
       }
   }

3. В App::pump при обработке Ev::JobDone { id, .. }:
   if self.progress_id == Some(id) {

       self.progress_id = None;
       self.job_title = None;
       if let Some((next_id, next_title, next_progress)) = self.pending_jobs.first() {
           let snap = next_progress.snapshot();
           if !snap.finished {
               let next_id = *next_id;
               let next_title = next_title.clone();
               let next_progress = next_progress.clone();
               self.pending_jobs.remove(0);
               self.progress_id = Some(next_id);
               self.job_title = Some(next_title);
               self.progress = Some(next_progress);
               self.speed = (Instant::now(), 0, 0.0);
           } else {
               self.pending_jobs.remove(0);
           }

   }
   self.pending_jobs.retain(|(pending_id, _, _)| *pending_id != id);

4. В App::update при busy учитывать и pending_jobs:

5. В статус-баре при наличии pending_jobs добавить в правую часть:
   if !self.pending_jobs.is_empty() {

           &pick("+{count} в фоне", "+{count} in background"),

Тест: не автоматизируется (UI). Ручной сценарий в SOP.txt раздел 13.2,

  pub fn find_game_root(dir: &Path) -> PathBuf {
      if has_game_marker(dir) {
          return dir.to_path_buf();
      }
      let mut queue = vec![(dir.to_path_buf(), 0usize)];
      while let Some((path, depth)) = queue.pop() {
          if depth >= 4 {
              continue;
          }
          for child in subdirs(&path) {
              if has_game_marker(&child) {
                  return child;
              }
              queue.push((child, depth + 1));
          }
      }
      let dirs = subdirs(dir);
      let files = fs::read_dir(dir).map(|e| e.flatten().filter(|x| x.path().is_file()).count()).unwrap_or(0);
      if dirs.len() == 1 && files == 0 {
          dirs.into_iter().next().unwrap()
      } else {
          dir.to_path_buf()
      }
  }

## Известные ограничения (не в scope этих задач)

Следующие проблемы известны, но их исправление — отдельный проект. Не
трогать в рамках текущих задач.

1. App — бог-объект (~55 полей). Разделение на AppState/UiState/JobState
   — рефакторинг на несколько дней.
2. .clone() в catalog_view/builds_view/installed_view на каждый кадр.
   Работает, для 100 модов не заметно. Оптимизация — через Arc или
   индексы — отдельная задача.
3. Нумерация версий (2.1.0 → 2.1.5 без промежуточных). Решение владельца.
4. ARCHIVE_ITEMS захардкожен. Если зеркало уйдёт — целая эпоха версий
   исчезнет. Вынести в конфиг — отдельная задача.
5. dist-сумма размеров сборок в u64. Не переполнится на реальных данных.
6. Нет проверки контрольных сумм скачанных файлов. Осознанное решение
   (SOP.txt раздел 14).
7. Нет автообновления лаунчера. Non-goal (SOP.txt раздел 4.3).
8. sort_groups пересортировывает на каждом кадре. Для 100 модов не
   заметно, для 500 — заметно. Оптимизация — отдельная задача.
9. DwmSetWindowAttribute 35/34/36 — только Windows 11. На Win10 меняется
   только тёмный/светлый заголовок. Косметика, не код.
10. Кэш обложек без лимита размера. Растёт неограниченно. Отдельная задача
    (политика вытеснения).
11. net::describe для Transport может выдать внутренний адрес прокси в
    строке ошибки. Не критично, но видно в логах.
12. Progress::stage сбрасывает file_index/file_total. При переходе
    «скачивание → распаковка» счётчик пропадает и появляется снова.
    Косметика.
